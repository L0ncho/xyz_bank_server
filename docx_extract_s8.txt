Introducción a la semana
En esta última semana, consolidarás todo lo aprendido sobre microservicios y resiliencia en la nube con Spring Cloud, integrando seguridad, tolerancia a fallos y escalabilidad en un sistema backend moderno. Aplicarás los conceptos clave adquiridos en semanas anteriores para desarrollar una solución completa, lista para entornos productivos.
Durante este proceso, profundizarás en la implementación de Spring Cloud Security, configurando mecanismos de autenticación y autorización con OAuth 2.0 y JWT, asegurando la protección de los datos y servicios distribuidos. También reforzarás la tolerancia a fallos con Resilience4j, aplicando Circuit Breakers, Retry Policies y Bulkheads para garantizar la estabilidad y disponibilidad de los microservicios ante interrupciones.
Además, trabajarás con mensajería asíncrona mediante Kafka y JMS, diseñando una arquitectura orientada a eventos que optimiza el flujo de datos en sistemas distribuidos. Finalmente, aprenderás sobre conteinerización con Docker y Docker Compose, preparando tu aplicación para un despliegue eficiente y escalable en la nube.
Esta semana representa el cierre de tu aprendizaje, donde integrarás todos los componentes de una arquitectura backend avanzada, segura y resiliente. Al finalizar, estarás preparado para enfrentar los desafíos del desarrollo en la nube y diseñar soluciones altamente escalables, seguras y preparadas para producción.

Spring Cloud Security
Cuando trabajas en un sistema distribuido basado en microservicios, una de las mayores prioridades es garantizar que cada solicitud que llega a tu sistema sea realizada por usuarios o servicios autorizados. Imagina que tu sistema es como un gran edificio con muchas habitaciones, donde cada habitación representa un microservicio específico. Cada puerta del edificio tiene diferentes requisitos para ser abierta, dependiendo de quién eres y qué necesitas hacer. Por ejemplo, un empleado puede tener acceso a la sala de reuniones, pero no a la bóveda de seguridad.
Ahora, piensa en cómo podrías gestionar este acceso. Podrías crear reglas personalizadas para cada puerta y escribir código específico en cada servicio para manejar estas reglas. Sin embargo, esto se vuelve complejo y difícil de mantener cuando tienes docenas o cientos de microservicios. Por suerte, existen soluciones estándar que resuelven este problema de manera eficiente, como el protocolo OAuth 2.0. Estas soluciones nos ayudan a centralizar la autorización y reutilizar patrones probados en la industria.

Conceptos clave
Figura 1
Diagrama de secuencia de OAuth 2.0

Nota. Esta imagen muestra cómo es la interacción de manera ordenara entre un cliente y un servidor de recursos. Israel, A. (2024). OAuth2 in Simple Terms. https://www.propelauth.com/post/oauth2-in-simple-terms

La Figura 1 nos muestra cómo se realiza una interacción cuando hay un Authorization Server disponible implementando OAuth 2.0. Para comprender la figura, te explicamos los conceptos más importantes de la interacción:

Servidor de autorización (Authorization Server)
Es como un guardián centralizado que verifica quién eres y qué permisos tienes. Este servidor genera un token de acceso que actúa como tu pase para moverte por las diferentes habitaciones del edificio (microservicios).

Token de Acceso (Access Token)
Es un "pase" temporal que obtienes del servidor de autorización. Este token contiene información codificada, como tu identidad y los permisos que tienes. Los microservicios validan este token antes de permitirte acceder.

Servidor de recursos (Resource Server)
Representa las puertas del edificio. Cada microservicio actúa como un servidor de recursos que valida el token de acceso antes de permitir que interactúes con los datos o servicios protegidos.

Flujo de autorización
Es el proceso mediante el cual obtienes el token de acceso. Incluye pasos como autenticación del cliente (asegurar que eres quien dices ser) y autorización del usuario (asegurar que tienes permiso para acceder a un recurso).

Delegación de Seguridad
En lugar de que cada microservicio implemente su propia lógica de autenticación, todos delegan esta tarea al servidor de autorización. Esto simplifica el código y mejora la seguridad.

Implementación
Para ver una implementación de un servicio que gestiona identidades en tu proyecto de microservicios, puedes usar el proyecto “Spring Authorization Server”.

Conteinerización y Cloud
Cuando trabajas en un sistema moderno, necesitas que tus aplicaciones sean portátiles, escalables y fáciles de desplegar. Aquí es donde Docker se convierte en una herramienta esencial. Como ya debería saber, Docker te permite empaquetar tus aplicaciones junto con todas sus dependencias en contenedores, pequeños "paquetes" que aseguran que tu aplicación funcione de la misma manera en cualquier entorno, ya sea en tu computadora, un servidor de desarrollo o un sistema de producción en la nube.

¿Qué es Docker y por qué usarlo?
Docker es una plataforma de conteinerización que simplifica la forma en que desarrollas, despliegas y ejecutas aplicaciones. Con Docker puedes:
Asegurar la consistencia entre entornos: una aplicación en un contenedor incluye todo lo necesario para ejecutarse: código, librerías, variables de entorno y configuraciones. Esto elimina problemas como "en mi máquina funciona".
Facilitar el despliegue continuo: los contenedores son portátiles y ligeros, lo que hace que moverlos entre entornos sea rápido y eficiente.
Optimizar recursos: a diferencia de las máquinas virtuales, los contenedores comparten el kernel del sistema operativo, ocupando menos espacio y cargando más rápido.

Iniciando con Docker
Con Docker trabajarás principalmente con dos conceptos clave: imágenes y contenedores.
Imágenes: son plantillas que incluyen tu aplicación y todo lo que necesita para ejecutarse. Puedes crear tus propias imágenes o usar imágenes predefinidas desde el Docker Hub, una biblioteca pública de imágenes.
Contenedores: son instancias ejecutables de una imagen. Cada contenedor es independiente, pero puede interactuar con otros si lo configuras.

Despliegue de contenedores en la nube
Docker no solo facilita el desarrollo local, también simplifica el despliegue en la nube. Con plataformas como AWS, Azure o Google Cloud, puedes orquestar tus contenedores y garantizar que estén disponibles incluso en caso de fallos.

Usando Docker Compose para gestionar múltiples servicios
En sistemas distribuidos, es común que varios servicios trabajen juntos, como un backend, una base de datos, un proxy inverso, servicios de mensajería tipo Kafka, RabbitMQ, entre otras dependencias. Docker Compose te permite definir y gestionar todos estos servicios en un solo archivo docker-compose.yml.

Explorando resiliencia en entornos distribuidos con Docker
La resiliencia es clave en sistemas distribuidos. Docker te permite implementar estrategias como:
Reinicio automático: configura tus contenedores para que se reinicien automáticamente en caso de fallo.
Balanceo de carga entre contenedores.
Escalado horizontal: lanza múltiples contenedores de un servicio para manejar más usuarios o tareas.

Preparación para producción con Docker
Antes de llevar tus contenedores a producción, como una buena práctica, asegúrate de:
Optimizar tus imágenes: usa comandos como docker image prune para limpiar imágenes no utilizadas.
Implementar monitoreo: usa herramientas para supervisar tus contenedores.
Habilitar copias de seguridad: configura respaldos automáticos para los datos que manejan tus contenedores. Esto lo puedes hacer directamente en cada motor de base de datos o plataforma de datos que utilices.
